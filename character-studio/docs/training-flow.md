# 角色训练与评估流程（0.6）

## 两种训练

内置执行器做提示策略搜索与评估，每次调用 DeepSeek 都是新上下文，不修改参数。外部 SFT/LoRA 才是权重训练；本版仅提供经过批准的训练示例导出，没有连接权重训练服务。

缺少生平、人物关系或角色说过的话，应优先继续研究。提示训练主要约束已有材料如何被使用，例如别把梦境当现实、别凭空拿出道具、别把推断写成亲历。没有跨场景语言证据时，语言相似度评分设上限，不能因回答流畅就给高分。

## 数据隔离

先冻结 corpus 与数据集。每题包含 id、split（train/dev/test）、scene_cluster_id、input、criteria，可选 state。三个分区都必须存在；同场景簇和同问题不得跨区。独立上下文能排除会话记忆，不能证明模型预训练没有见过原作。

演员仅接收角色卡、当前场景、状态与输出格式。评分器另开上下文，拿到判据和统一证据卡。当前演员与自动评分器可用同一模型，因此不等于独立专家评审。人工对盲测结果的复核仍必要。

## MCP 调用顺序

1. 用已保存 research_id 或 corpus 加 dataset 调用 create_training_run，只生成计划，不收费。
2. 查看计划、预算、材料缺口；run_training 显式 execute:true 才执行模型调用。max_calls 为硬上限，不自动重试失败或不确定的请求。
3. 训练集尝试有限个通用策略；开发集选版；冻结后才打开最终测试。已保留或已暴露的测试场景簇不能在以后计划里再次使用。每轮需要新的独立最终测试场景。
4. training_status 读取结果。严重错误、资料不齐、诊断草稿或未达维度阈值的修订不得激活。
5. activate_training_revision 激活合格版本；prepare_roleplay 会读取激活策略；rollback_training_revision 可恢复上一版。

允许 allow_draft 仅用于诊断缺资料时的失败模式，不绕过部署门槛。相同运行不能意外重新执行并重复计费。

## 状态与动作

角色卡里的“懂医术”不等于当前携带某种药。inventory 和 abilities 只接受确认的当前资源；空列表默认表示未确认，不能推断角色永远没有。回复必须分离 speech、actions、world_claims；资源 ID、证据 ID 和状态哈希经过检查。无法确认的动作应改为观察、询问或提出条件，不直接控制外部执行器。

## 何时考虑权重训练

先积累覆盖不同人物关系、情绪压力、道德抉择、拒绝、未知问题和行动限制的原作依据及人工审核范例。开发集和测试集持续保留，比较角色名基线、资料卡、提示迭代和外部权重训练，使用新场景、人评与多次重复。

export_finetune_dataset 只导出 TRAIN 中明确批准并绑定原作证据的示例。人工批准字段是声明，不提供身份认证。导出成功不代表已训练或部署；外部训练器的模型许可、接口和费用应在接入时具体确定。不得用模型自行编写且未经核验的设定持续自我训练。
